NEXIAM OMR Architecture — interactive learning map

Optical-mark capture for aptitude exams · OMRChecker engine · NEXIAM owns the answer key · the worker only proposes

The problem

Aptitude exams use bubble answer sheets. Staff photograph each sheet and NEXIAM must turn the photo into per-question answers — but a machine misread may never silently become a score. Everything below exists to guarantee one sentence:

The OMRChecker engine proposes marks. NEXIAM validates, shows evidence to staff, and only after human confirmation compares against its own answer key. The engine never receives the key, the roster, scores, or database access.

Two halves of the world

ENGINE WORLD Template — the blank sheet

  • template.json — where every bubble lives (field blocks: APPLICANT_NUMBER, VERBAL, QUANT)
  • config.json — engine thresholds
  • reference.svg — what the sheet looks like
  • Authored in OMRChecker's native format — outside NEXIAM
  • Pinned in NEXIAM as an immutable, hash-addressed NativeBundle

NEXIAM WORLD Booklet — the exam content

  • Which questions exist, grouped by aptitude area (Verbal / Quantitative)
  • The answer key (correct option per question) — private, stored as a SHA-256 hash
  • Points at template questions for bubble geometry
  • Versioned; a pair approves "booklet X v2 reads on template Y v1"

Why separate? The same sheet layout can serve many exams (or shuffled-key variants to stop copying), and the answer key must never cross the provider boundary.

Environment gotcha worth knowing

PHPUnit 12 applies <env force> to $_ENV + putenv only — never $_SERVER. Laravel's env() reads $_SERVER first, and the app image runs variables_order=EGPCS. So a Compose environment: entry silently beats phpunit.xml. Rule: never put OMR_PROVIDER / OMR_ALLOW_FAKE_PROVIDER in compose.yaml. Tests select the fake provider; the dev runtime defaults to omrchecker fail-closed.
