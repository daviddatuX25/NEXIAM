## Why

Staff currently author OMR answer sheets only through script-driven layout prediction (the semantic blueprint solver), which cannot represent supplier forms (HTML, DOCX, PDF, or scanned images) with print-exact fidelity. The founder requires a staged canonical-document builder: every source converges to a canonical exact-size page raster that staff map block/row geometry onto by hand, every new production template carries the mandatory four-corner marker registration (upstream-first marker profile, candidate-to-qualify, promoted to qualified only on evidence), and blank answer-sheet print instances are identified by a signed, versioned QR that is NOT applicant identity.

## What Changes

- **NEW** `omr-canonical-template-authoring` capability: staged authoring of canonical OMR templates from HTML, DOCX, PDF, image, and current preset sources.
- **NEW** Adapter contract: HTML (sanitized via a RESEARCHED/PINNED server-side allowlist sanitizer with CSS filtering, remote-off, deterministic output; unrecognized `{{…}}` or dynamic-looking tokens rejected unless represented by fixed allowlisted `data-omr-overlay` slots; plain static text fine), DOCX (LibreOffice→PDF exactly once), PDF (MediaBox inspection), image (EXIF; no-profile/sRGB accepted, non-sRGB converted only by a researched deterministic pipeline or typed `image_icc_unsupported`; white-flatten), and preset → intermediate page images + detected physical metadata + provenance. Preset geometry is transformed by a NORMALIZED physical transform from the actual old page dimensions of the rendered PDF (not a fixed PPI ratio; the 242 PPI label is not exact physical DPI). Authoring photos require manual-confirmed quadrilateral rectification where the frontend may suggest/drag corners but the SERVER is the authority via the worker seam `POST /v1/source-rectification` (bounded child, existing HMAC envelope), returning the rectified raster + quality gates; every source passes secure hostile-file preflight before conversion. Staff reject reasons for source pages are user classifications, not automatic wrong-page claims; ordinary capture never exposes a manual quad.
- **NEW** Versioned `omr_marker_profiles` domain: code+version unique, family, asset path/hash, physical size_mm, quiet_zone_mm, matching options/config JSON, status `candidate|qualified|retired`, qualification evidence hash, created/qualified-by/at. The upstream OMRChecker sample marker starts as a candidate; the current custom fiducial profile is a comparison candidate. Candidate qualification is TEMPLATE-INDEPENDENT: a SYSTEM marker-calibration artifact/sheet generated by the canonical renderer (four candidate markers + a controlled background/corner false-positive corpus), bound to marker asset hash + renderer version + printer/device/paper evidence, promotes ONE profile to `qualified` (others retire); a draft selects `marker_profile_id`; compile requires a qualified profile; staff adjust insets only.
- **NEW** Authoring drafts: incomplete staged work lives in `omr_template_authoring_drafts` (code/name, source_kind, stage, marker_profile_id, authoring_json, lock_version for optimistic autosave, owner, compiled_version_id) with assets in `omr_template_assets` (nullable `authoring_draft_id` and `template_version_id` FKs with a DB CHECK that exactly one is non-null; kind, page_no, path, mime, bytes, sha256, metadata). A compile action (`CompileOmrCanonicalDraft`) requires the current mapping, a qualified marker profile, AND digital verification, then atomically creates the immutable template version (status `draft`), transfer/copy-pins assets and evidence to version ownership (provenance source assets are NEVER garbage-collected), and freezes the canonical PDF/bundle; the final version stores only a compact authoring manifest/hash.
- **NEW** Stage sequencing: authoring-draft stages `draft → source_confirmed → page_prepared → mapping_complete → digital_verified → compiled`; digital proof runs DRAFT-scoped before compile; physical qualification runs VERSION-scoped AGAINST the exact compiled template version/PDF and binds to version+renderer+marker-profile hashes; activation requires a compiled version plus `physical_qualified` and atomically swaps the active version. Physical qualification is NEVER required before compile.
- **NEW** Staff page confirmation: after ingestion, staff confirm each physical page of the intermediate output before Stage-2 composition begins; a page staff reject is recorded with their typed reason and a re-ingest path.
- **NEW** Canonical composition: exact-size 300-PPI PNG per page plus an exact-size image-backed PDF print authority; physical mm stored and deterministically converted (`round(mm × 300 / 25.4)`); proportional scale, X/Y offset, 9-point alignment, white padding only; proportional visual ENLARGEMENT allowed only when the effective source DPI after physical placement stays at or above the source-type-aware floor (no detail invented); one size/orientation for all pages in v1; typed rejection lists mixed offending pages. The system controls exact PDF dimensions and internal renderer scale=100%; it cannot enforce an external printer dialog's Fit setting — the UI instructs/warns, and physical qualification verifies measured print output.
- **NEW** Independent per-side mm settings (printer-safe margin, marker-center inset, content margin) recorded per page; four OMRChecker-compatible markers mandatory for every NEW activated template (the system adds no registration border, no three-of-four fallback). The system does NOT reject an imported supplier border — the corner-pattern false-positive probe must prove borders/decorative corners/partial markers do not register; only the system-generated registration border is absent by design. `pageDimensions` = marker-center rectangle.
- **NEW** Overlay layer before mapping: template-time fixed boxes (static text/logo/writing boxes) and fixed dynamic slots. Allowed tags: institution/assessment/template plus `blank_instance_code`/`page_number`/`page_count`/`blank_instance_qr`. **NO applicant tags.** Fixed boxes, no reflow; HTML source dynamic slots are fixed `data-omr-overlay` markers. Dynamic instance QR/page numbers render at print-job scope; the canonical static raster excludes per-instance values. The blank-instance QR is opaque AND signed/versioned (instance code + page no/count + signing key id + HMAC); it identifies only the opaque page-set instance/page and prints a unique checksummed display-code fallback.
- **NEW** Mapping authority: native Svelte SVG scene (raster `<image>` underlay, native pointer events, **no Konva/Fabric**), viewBox and storage in canonical pixels with inverse-CTM conversion (inspector derives mm); overlay drag/resize with 4px snap; OMR block/grid and per-row uniform structural adjustment; keyboard 1px / Shift+Arrow 10px; individual bubbles inspect-only; existing `fieldBlocks` remain the recognition-geometry authority with the compiler/bundle asset manifest and worker envelope allowed to extend (QR decode, item evidence) while the recognition algorithm and `fieldBlocks` contract stay pinned.
- **NEW** Mapping validation: unique contiguous labels, missing-question warnings, supported regular options (v1 MCQ4/MCQ5/int), duplicate/overlap/out-of-bounds/marker/content/identity/header collisions, minimum physical bubble diameter/pitch, source/bundle page-count parity; irregular option spacing unsupported in v1. Overfull rows are never auto-fixed: staff explicitly split a block into one-label regular blocks, preview, then the validator rechecks.
- **NEW** Hash invalidation: any source/composition/overlay change invalidates the stored mapping and all verification hashes; compiled/activated versions are read-only and the previous active version stays live until the replacement activation commits. Autosave optimistic locking uses the draft `lock_version`, never the immutable template version.
- **NEW** Blank answer-sheet instances: additive `omr_blank_instances` (set row) plus `omr_blank_instance_pages` (per-page rows with signed-payload hash, signing key id, and print artifact hash), **never an applicant FK**; ≥128-bit instance code (e.g., 26-char Crockford base32 random) plus a UNIQUE short checksummed `display_code` for human fallback (lookup aid, never a security authority); the set stores `qr_manifest_hash` = hash of the ordered per-page signed payload hashes (every page payload differs), with per-page `qr_payload_hash` retained; `printed|captured|superseded|void` lifecycle with a `signing_key_id` keyring so key rotation still verifies historical prints; a set stays `printed` while partially captured (page progress derives from page rows) and becomes `captured` only when ALL required pages are captured; superseding a partially captured set requires explicit whole-set replacement with audit (old page captures remain evidence); chunked high-volume printing with idempotent retries, per-page partial-failure representation, chunk manifest/download/ZIP behavior with preserved page order; typed capture issues for duplicate/missing/mixed pages, tamper, and template mismatch. Manual damaged-QR recovery is an explicit audited fallback: a payload present but signature/key-invalid is a HARD `qr_signature_invalid`/`qr_key_unknown` that manual entry MUST NOT override; when the payload cannot be decoded or is absent, capability-gated staff may enter the unique checksummed display code, the server resolves the set/page/template from the DB, explicit confirmation is required, `instance_resolved_manually` is recorded, and recognition remains blocked until confirmed.
- **NEW** Test capture evidence: whole normalized page + OMRChecker `draw_template_layout`; interactive per-item/row evidence driven by the DECLARED OPTION SET (A–D for MCQ4, A–E for MCQ5, 0–9 for int; A–D is the common example) — circles/rectangles, crops, means, threshold delta/status, field-block shifts, marker matches; result carries source/mapping/bundle hashes; read-only with a `Return to mapping and select row` path; thresholds remain `Unqualified` until physical calibration.
- **NEW** Verification gates: digital proof generator starts from the final composed PDF on the DRAFT, programmatically shades a deterministic declared answer vector derived from mapped labels (a paired booklet is NOT required for template proof; booklet compatibility is tested separately when pairing exists) and adds the signed instance QR; it adds a deterministic identity shading ONLY when a mapped identity grid exists (never a fabricated identity field); then runs the full no-go matrix (clean/perspective/rotation/light/blur/glare/low-res/partial/missing-marker/wrong-marker/wrong-instance/superseded/duplicate/multipage-order); after compile the digital proof repeats as a hash-parity smoke against the frozen PDF/bundle. TEMPLATE physical qualification runs after compile against the compiled version, binds evidence to template version + canonical renderer version + the ALREADY-QUALIFIED marker profile, records printer/device/paper, and gates activation (it never re-qualifies the profile — profile qualification is template-independent via the calibration artifact); states `draft → source_confirmed → page_prepared → mapping_complete → digital_verified → compiled` then version-scoped `physical_qualified → active`.
- **NEW** Physical suitability: minimum physical bubble diameter and effective-DPI floors validated before activation (research-grounded: ≥4.2 mm bubbles, ≥150 effective DPI capture).
- **NEW** Security/ops: file magic + extension match, DOCX zip/content-types/document-XML checks with VBA/macro rejection and decompression/member caps, PDF xref/page-count checks with encrypted/password rejection, HTML sanitization via a researched/pinned server-side allowlist sanitizer with no scripts/events/remote assets, image EXIF handling with non-sRGB ICC converted only via a researched deterministic pipeline or typed `image_icc_unsupported`, transparency/DPI-floor handling, bounded pixel budgets (per-page and per-job) plus physical custom-size bounds, upload/memory/time/concurrency limits, queued heavy conversion with progress/cancel/retry (no pause), converter-version/settings hash provenance, private SHA-256 storage chain, temp cleanup/orphan GC that NEVER removes provenance source assets, rate limits, capability authz + audit on every new action, staff-only diagnostics. DB CHECK constraints enforce stage/status/page_no/page_count values, exactly-one asset owner, unique display codes, and terminal lifecycle transitions are enforced in actions plus tests. A maintained server-side QR renderer (deterministic SVG/PNG, fixed ECC/quiet zone, license/security/version vetted, no network) is researched and pinned in the FOUNDATION phase, completed BEFORE QR rendering implementation tasks; npm `qrcode` cannot serve the PHP queue runtime by itself.
- **NEW** UX stage model (Start → Convert/inspect → Prepare page → Overlay → Map → Digital verify → Compile → Physical qualify/Activate → Blank print) with explicit loading/empty/error/blocked/conflict/success/recovery states per screen, full ASCII wireframes per stage (Start source cards; Convert progress/metadata/photo-quad; Prepare three-column controls/preview/layers; Overlay/tag editor; Map; Digital verify item evidence; Compile readiness; Physical qualification+activate; Blank print quantity/chunks/history/replacement/manual QR recovery with the two-branch contract), a per-stage state/microcopy table, back/unsaved/focus handling, responsive breakpoints (phone view-only, tablet ≥1024px editor), and an actual-size print instruction/warning on every print surface. Stages 1–7 are draft-scoped; compile pivots the same workflow shell to the compiled version for stages 8–9; Blank print stays disabled until the version is active.
- **MODIFIED (frontend only, phased, BREAKING on cutover)** Template builder: old builder retained during parity, hidden only after a semantic parity checklist using normalized transforms from actual page dimensions (same pages/labels/options, physical centers/regions and normalized review regions within declared tolerance, deterministic recognition exactness, visual diff threshold — NOT byte-identical hashes across render paths; canonical repeated runs hash equal), then removed in a clean cut (no permanent dual builder); current solver retained temporarily as the preset adapter; historical markerless immutable scan support remains read-only forever.
