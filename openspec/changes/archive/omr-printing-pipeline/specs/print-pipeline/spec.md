# print-pipeline Spec

## ADDED Requirements

### Requirement: Async print jobs never block requests

Every printable artifact SHALL be rendered by a queued job that persists a `print_jobs` row (`queued → rendering → ready | failed`) with artifact type, scope, file path, checksum, safe error code, and progress counters. Request handlers MUST return immediately with the job reference; the UI SHALL poll status and offer downloads only for `ready` jobs.

#### Scenario: Single result sheet requested
- **WHEN** staff request a result sheet for one applicant
- **THEN** a print job row is created and the response returns immediately with the job id

#### Scenario: Rendering failure is truthful
- **WHEN** a render job fails
- **THEN** the job becomes `failed` with a safe typed code and the UI shows failure, never silent success

#### Scenario: Download only when ready
- **WHEN** staff request a download for a job that is not `ready`
- **THEN** the download route refuses with a typed not-ready response

#### Scenario: Bulk progress
- **WHEN** a bulk job renders many sheets
- **THEN** the job exposes progress counters the UI polls

### Requirement: Derived bundle renderer is the single visual source

All sheet visuals SHALL be drawn from the bundle's `template.json` (pages, blocks, origins, gaps, bubble sizes) at render time. Option letters and digit labels MUST be centered on their bubble centers by construction; page headers, row numbers, margins, and paper size MUST come from geometry and config. Hand-authored reference SVGs SHALL NOT be the render path.

#### Scenario: Letter alignment
- **WHEN** any bundle version renders
- **THEN** every A–D / 0–9 label center equals its bubble center within rounding

#### Scenario: Page count fidelity
- **WHEN** a two-page bundle renders blank sheets
- **THEN** the output has exactly one PDF page per sheet page with `PAGE X OF N` headers

#### Scenario: Paper mapping
- **WHEN** paper is configured as long bond (216×330mm)
- **THEN** a long-bond bundle prints 1:1 with configured margins and nothing clipped

#### Scenario: Paper mismatch never scales geometry
- **WHEN** a bundle's pageDimensions do not match the configured paper
- **THEN** rendering refuses with a typed error or letterboxes with visible cut marks — bubble geometry is NEVER scaled

#### Scenario: Print-fidelity guard
- **WHEN** a blank sheet renders
- **THEN** the output includes a measurement/calibration strip and a "print at 100%, no fit-to-page" instruction block

### Requirement: Blank answer sheets from the native template

Blank sheets SHALL render for an active template version through the pipeline, using the same geometry the engine pins. The physical test kit SHALL be generated by the same renderer.

#### Scenario: Render blank sheet
- **WHEN** staff request blank sheets for an active template version
- **THEN** a queued job produces one PDF page per sheet page at the configured paper size

#### Scenario: No active version
- **WHEN** staff request blanks for a template without an active version
- **THEN** the request is refused with a typed error

### Requirement: Result sheets with scores and printed tracking

Result sheets SHALL include applicant identity, per-area raw and converted scores, descriptive ratings where configured, an institution header, a counselor signature block, and a watermark. Printed tracking SHALL live on the release record per release version: `result_printed_at` on `ResultRelease` (so a re-release after correction starts unprinted). On a `ready` render for released records, `result_printed_at` MUST be set (idempotently).

#### Scenario: Single result sheet content
- **WHEN** a result sheet renders for a scored applicant
- **THEN** the PDF contains identity, every aptitude area score with converted value, ratings, and the signature block

#### Scenario: Bulk generation
- **WHEN** staff request bulk result sheets for a session
- **THEN** one job renders all sheets with progress counters and each applicant's file is downloadable when the job is `ready`

#### Scenario: Printed status recorded
- **WHEN** a result sheet job completes for released records
- **THEN** `result_printed_at` is set on those release records and visible in the release surface

### Requirement: Sensitive storage and authorized downloads

Result sheets SHALL store on the sensitive disk with HMAC; blank sheets MAY use the normal private disk. Downloads MUST re-authorize capability + scope and stream with `private, no-store`.

#### Scenario: Protected result sheet download
- **WHEN** an authorized staff member downloads a ready result sheet
- **THEN** the file streams with `private, no-store` headers

#### Scenario: Unauthorized download refused
- **WHEN** a staff member without the release capability requests a result sheet download
- **THEN** the route denies access without existence leakage

### Requirement: Manual printed-status toggle (legacy parity)

Staff SHALL be able to mark a set of release records printed or clear the mark independently of rendering (physical print failures, externally printed stacks), capability-gated and audited.

#### Scenario: Mark a stack printed
- **WHEN** staff mark released records printed after a physical print run
- **THEN** the records show printed status and the change is audited

#### Scenario: Clear a misprint
- **WHEN** staff clear the printed mark
- **THEN** the records show unprinted status and the change is audited

### Requirement: Print job audit trail

Every print job creation, ready/failed transition, and download SHALL record an audit event with actor, artifact type, scope, and checksum; the `print_jobs` row SHALL carry the requesting actor.

#### Scenario: Who printed what is auditable
- **WHEN** any job is created, completes, fails, or is downloaded
- **THEN** an audit event names the actor, artifact, scope, and checksum

### Requirement: Bulk jobs carry per-item files and partial states

Bulk jobs SHALL persist a per-item manifest (applicant id → path + checksum) and per-item statuses (pending/rendered/failed with safe errors). A bulk job with some failed items SHALL reach `ready`-with-partial so successful sheets are downloadable while failures are listed.

#### Scenario: Bulk with one unrenderable applicant
- **WHEN** one applicant in a bulk job cannot render
- **THEN** the job completes with partial status listing the failed item and its safe error

### Requirement: Print job retry from pinned inputs

A failed print job SHALL be retryable from its pinned inputs (artifact identity: bundle hash for blanks; release version + document checksum for result sheets, recorded at creation). Retry SHALL refuse with a typed error when the pinned input is no longer current.

#### Scenario: Retry a failed job
- **WHEN** staff retry a failed job whose pinned input is still current
- **THEN** a new render attempt runs from the same pinned input

#### Scenario: Stale input refusal
- **WHEN** the pinned release version was superseded before retry
- **THEN** retry refuses with a typed stale-input error

### Requirement: Duplicate job detection

Requesting an artifact for a scope that already has a queued/rendering/ready job SHALL return the existing job instead of creating a duplicate.

#### Scenario: Concurrent duplicate request
- **WHEN** two staff request the same artifact simultaneously
- **THEN** both receive the same job id and one render occurs

### Requirement: Blank sheets for retired-but-pinned versions

Blank sheets SHALL render for any template version referenced by an open capture batch, even when retired; refusal applies only to versions with no open batch and no active status.

#### Scenario: Blank sheets for a retired pinned version
- **WHEN** a retired template version is pinned by an open batch
- **THEN** blank sheets for that version still render

### Requirement: Ready-artifact retention

Ready artifacts SHALL be deleted by a scheduled retention pass N days after completion/download (N configurable); the sensitive disk SHALL NOT grow unboundedly.

#### Scenario: Retention pass
- **WHEN** a ready artifact passes its retention window
- **THEN** a scheduled pass deletes it and records the cleanup
