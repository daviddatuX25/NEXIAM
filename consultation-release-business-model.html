1 · Where consultation/release sits in the system

The greenfield modular monolith (GF-18 §2/§3). Every row is a real module/aggregate in app/. Assessment (scoring) feeds Release; Release owns consultation + documents; Authorization gates everything; Audit underlies it all.

2 · AS-IS — what's actually built today

Two aggregates exist (ConsultationDecision, ResultRelease) plus a document record. Everything else in the consultation workflow is missing.

3 · TO-BE — F2F-default + online branch (GF-06 §8.1)

The same Release module, two explicit branches. F2F (default): plan → batches → staff assignment. Online: plan → availability → applicant reservation. Both converge on the existing ConsultationDecision + ResultRelease (which gains a mode).

5 · Open decisions (need founder disposition)

D1Build sequence

F2F first (the default), online branch second?

Recommended: F2F-first — matches GF-06 "F2F is the default mode" and de-risks the online reservation concurrency.

D2Capability split

New GUIDANCE_CONSULTATION_PLAN for publish/assign, keep GUIDANCE_CONSULTATION_DECIDE for the final decision?

Recommended: yes — separates "runs the consultation office" from "records the outcome", same philosophy as the scheduling/monitoring split.

D3Release interlock

Add ResultRelease.mode (f2f/online) in this change, or defer?

Recommended: in this change — the two release branches are only distinguishable if release records carry the mode.
