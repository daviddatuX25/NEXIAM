## Interaction Specifications

### Two-Tier Sound System (D-09)

| Tier | Trigger | Frequency | Duration | Gain | Description |
|------|---------|-----------|----------|------|-------------|
| background | Poll-based notification arrival (45s polling) | 600Hz -> 400Hz sweep | 0.15s | 0.08 -> 0.001 | Soft, short chime — unobtrusive ambient alert |
| action | Direct user action (publish, accept, reject, start, close) | 800Hz -> 400Hz sweep | 0.3s | 0.2 -> 0.001 | Louder, longer chime — confirms user's action |

Implementation: Add `playChime(tier)` to `notification-sound.js`. Modify `toast.js` to call `playChime('action')` for `success()` and `error()`, and `playChime('background')` for `message()` and `info()`. The existing `playNotificationSound()` function remains for backward compatibility but is updated to use the 'action' tier.

AudioContext fix: Add `if (audioContext.state === 'suspended') { audioContext.resume(); }` to `getAudioContext()` in both `notification-sound.js` and `toast.js`.

### Mobile Notification Dropdown (D-10)

Current: `w-80 sm:w-96` and `max-h-96`
Updated: `w-[calc(100vw-2rem)] sm:w-96` and `max-h-[80vh] overflow-y-auto`

This ensures the dropdown fills nearly the full viewport width on mobile and allows scrolling up to 80% of viewport height, preventing overflow.

### Date Grouping for My Sessions (Claude's Discretion)

Server-side grouping using Carbon methods (per RESEARCH.md recommendation):

| Group | Carbon method | Scope |
|-------|--------------|-------|
| Today | `isToday()` | Sessions happening today, regardless of status |
| Upcoming | `isFuture() && !isToday()` | Future sessions, sorted by date ascending |
| Past | `isPast() && !isToday()` | Past sessions, sorted by date descending |

Groups are rendered as collapsible sections with clear headers. In-progress sessions always appear at the top of "Today" group regardless of sort order.

### Pagination vs Infinite Scroll (Claude's Discretion)

**Pagination** — consistent with existing TestAdmin/Index.svelte pattern. Standard Laravel pagination with prev/next links. Infinite scroll would conflict with the polling refresh in NotificationDropdown and adds scroll-position complexity for date-grouped lists.

### Session List Card Layout (D-15)

Each session row/card displays:
- Date and time (left-aligned, primary info)
- Room name (secondary info)
- Status badge (using existing `statusVariant()` mapping)
- Applicant count (muted foreground)
- Quick action buttons (context-dependent):
  - Published session: **Start** button (primary variant)
  - In-progress session: **Close** button (outline variant)
  - Any session: **Open roster** link
- In-progress sessions get `border-l-4 border-l-primary bg-primary/5` highlight

### Start/Close Session Buttons (D-03, D-04)

**Start session button:**
- Visible only when `status === 'published'` and `isWithinStartWindow === true`
- If outside start window without override: button hidden, show "Outside scheduled time" text
- If outside start window with override: show button with amber warning text
- Confirmation: none (single POST action)

**Close session button:**
- Visible only when `status === 'in_progress'`
- If present applicants lack submissions: show warning inline, button proceeds with confirmation dialog
- Confirmation: "Some applicants have not submitted yet. Close anyway?" with Cancel/Confirm

### Notification Recipient Rules (D-08)

| Event | Applicants | Assigned Proctors | Assigned Test Admins | Admins/Super Admins |
|-------|-----------|-------------------|----------------------|---------------------|
| Session published | Yes | Yes | Yes | No (they trigger it) |
| Session started | No | Yes | Yes | No |
| Session completed | No | Yes | Yes | No |
| Session cancelled | Yes | Yes | Yes | No |
| Session reopened | No | Yes | Yes | No |
| Exam reminder | Yes | No | No | No |

Email channels (D-11, D-12):
- Acceptance/rejection: `['mail', 'database']`
- Exam publish/cancel: `['mail', 'database']`
- All others (start, complete, reopen, reminder): `['database']` only
