  <action>
Create Svelte page at resources/js/Pages/Admin/Applications/Create.svelte

**Layout**: Use AuthenticatedLayout.svelte (admin context)

**Form fields** (from Apply.svelte patterns):
- first_name, middle_name, last_name, suffix (name block)
- birthdate, sex (demographics)
- email, phone (contact)
- address_line, city, province, zip_code (address)
- course_preference_1, course_preference_2, course_preference_3 (course dropdowns)
- appointment_id (dropdown - optional for staff per research)
- status (dropdown: pending/accepted/dismissed - visible on admin create)

**Course preference logic** (from Apply.svelte):
- $derived optionsFor2, optionsFor3 that filter out already selected courses
- $effect to clear dependent selections if primary changes

**Birthday validation**: 15-50 years range (same as Apply.svelte)

**Submit**: POST to /admin/applications via useForm from @inertiajs/svelte

**Key differences from Apply.svelte**:
- No "allow_apply" check - staff bypass window restrictions
- Show status dropdown on create (for bulk data entry scenarios)
- Show active academic year info but no window message
- Use AuthenticatedLayout (admin context)
- Submit to storeAdmin (not store)
- Include rejection_reason field (hidden, staff may need to add later)

Follow existing Svelte 5 patterns from Apply.svelte ($props, $derived, $effect, $form).

  <name>Task 2: Create Admin Edit.svelte page</name>
  <files>resources/js/Pages/Admin/Applications/Edit.svelte</files>
  <action>
Create Svelte page at resources/js/Pages/Admin/Applications/Edit.svelte

**Layout**: Use AuthenticatedLayout.svelte (admin context)

**Props received from controller** (via Inertia):
- application: object with all current values pre-populated
- courses: array for dropdowns
- appointments: array for appointment dropdown
- active_season: current academic year info

**Form fields** (same as Create.svelte):
- All personal info, course preferences, appointment, status
- Populated with $props().application values using $derived or form.setData

**$form.setData initialization**: On mount, initialize useForm with application values:
```svelte
let { application, courses, appointments, active_season } = $props();

const form = useForm({
  first_name: application.first_name,
  // ... all fields pre-populated
});
```

**Submit**: PUT to /admin/applications/{application.id} via $form.put()

**Key differences from Create.svelte**:
- Form pre-populated with application data
- All fields nullable (edit can be partial)
- Show rejection_reason textarea (staff can add/edit rejection reason on edit)
- Include submitted_at and processed_at as read-only display fields

Follow existing Svelte 5 patterns from Apply.svelte.
